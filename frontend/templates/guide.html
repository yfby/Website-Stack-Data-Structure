A STUDY PLANNER WITH A SAFETY NET

Plan the work. Recover the slip-ups.

StudyStack is a college study board. Its recovery tray is a real LIFO stack: the last task removed is the first task restored.

01

What the website is for

College work arrives from several courses at once. StudyStack keeps each task visible by status, course, priority, and due date. A student can add a task, move it through the board, and remove it when it no longer belongs.

The recovery stack protects against accidental removals. Instead of hunting through an archive, the student restores the newest removed task first — exactly the behavior people expect from undo.

02

How the stack works

The stack lives in backend/stack.py. Its HistoryBuffer class stores removed task IDs in a Python list. The end of the list is the top. Adding a removal uses push(); restoring uses pop(); the recovery page checks the next task with peek().

  • push(), pop(), peek(), and size() are O(1).
  • to_list() is O(n) because it copies the stack for SQLite storage.
  • The saved list is bottom-to-top, so reloading rebuilds the same stack.
  • Refreshing or peeking never removes a task.

Find your part of the project

One Flask project, three clear layers.

FRONTEND
frontend/templates/ contains the HTML/Jinja pages. frontend/static/style.css controls the responsive look and layout.
BACKEND
backend/app.py handles routes and validation. backend/stack.py contains the LIFO recovery stack.
DATABASE
database/db.py contains SQLite helpers, database/schema.sql defines the tables, and saved records live in database/data/workbench.sqlite3.
CHECKS
Run RUN_TESTS.bat for the website and CHECK_STACK.bat for the stack behavior. Details are in docs/STUDENT_ACTIVITY.md.

Flow: browser form → Flask route → Python stack and SQLite helpers → rendered page. Launch from the project root with START_WEBSITE.bat or python run.py.
